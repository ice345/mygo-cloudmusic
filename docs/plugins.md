# Plugins

Where this app is going: sources of music as plugins, installed from [the plugins page](https://mygo-music.egoist.dev/plugins) as [`egoist/mygo-music`](https://github.com/egoist/mygo-music) does, with NetEase staying built in as the first source. This file is the plan and its decisions; the state of each stage is in [`roadmap.md`](roadmap.md#6-plugins).

This is not a fix for NetEase's -460: that was the eapi's User-Agent, and is fixed in the built-in client ([`roadmap.md`](roadmap.md#decisions), 2026-11-24). The `mygo-music-netease-plus` plugin sends the same iPhone User-Agent beside Windows headers, and only gets past -460 by asking the web's endpoint first.

## What upstream is

`egoist/mygo-music` (AGPL-3.0, as this repository is) is this app's successor: the archived `egoist/mygo-cloudmusic` rewritten as a player that knows no service. NetEase, QQ Music, Spotify, Bilibili and the rest are plugins, [about thirty](https://github.com/topics/mygo-music-plugin) of them. Its pieces, which we port, not depend on:

| Upstream | What it does | Size |
|---|---|---|
| `internal/music` | the types a view knows (`Track`, `Album`, `Browse` …) and `Source`, the 50 things a source can do, with `Can(what)` for the views to hide what it can't | 480 lines |
| `internal/plugin` | the host: reads `plugin.json`, runs one JS file in [moejs](https://github.com/MoeForge/moejs) (a pure-Go engine, Apache-2.0, alpha), gives it `fetch`, `host.storage`, `host.crypto`, `host.webSignIn`, `host.spawn`, enforces permissions, makes a plugin a `Source` | 2,400 lines |
| `internal/app/sources.go`, `plugin_install.go`, `ui_source_settings.go`, `request_headers.go` | a library of answers per source, the switcher, install from GitHub, a zip, a folder or a `mygo-music://install-plugin?repo=owner/repo` link, and a plugin's settings | 1,200 lines |
| `examples/demo-plugin` | every export, with made-up data | 300 lines |

The plugin contract is in upstream's README (the exports and their shapes). We keep it as it is, so a plugin made for upstream runs here, and add to it only where NetEase needs more (below).

## Why it is a rewrite of the data layer

Upstream's views know `music.Track{ID string}`. Ours know `netease.Track{ID int64}`, with NetEase's fields: 653 references in 31 files of `internal/app` and `internal/player`, and about as many in tests. Plugins can only be sources if the views stop knowing NetEase. So the work is in the views, not the host; the host is mostly a port.

## Decisions

**IDs are opaque strings.** A track is `{Source, ID}`; the app never reads inside an ID. NetEase's are the decimal song ID, and a podcast episode is `<audioID>@<programID>`, since its comments, likes and page are the program's and its audio is another ID.

**NetEase is a `Source` written in Go**, in `internal/netease` beside the client, and the only one that doesn't need the host. Its ID is `netease`. What `Source` has no method for (events, a listener's page, the daily mix as a card, 私人 FM's trash, search for users) stays NetEase's own, through optional interfaces the views ask for (`src.(netease.Extras)`), and shows only while NetEase is the source. Nothing NetEase can do today is dropped.

**`music` adds what NetEase needs.** `LyricLine.Reading` and `Lyrics.Reading` carry 音译, which upstream has no place for; a plugin that leaves them out has none. NetEase's own source turns its texts into lines with `lyrics.Build`, so word-timed lyrics, merged lines and translations keep the logic that is tested; `lyrics.FromMusic` turns `music.Lyrics` into `lyrics.Line` again. A line's words go across only where they carry their own times, and the others share the line's time as they always did, so the round trip is exact (`TestLinesSurviveTheSourcesShape`). `Leveler` lets a source name its levels of audio (NetEase has five; upstream's `Qualities` has three), which the cache keeps songs by.

**A track carries its source's record.** `Track.Extra` holds the source's own record of a track (NetEase's whole `netease.Track`: the fee, the privilege, an episode's program and podcast), which the app never reads, and the queue and the session keep. While views still hold `netease.Track`, `internal/app/bridge.go` turns one into the other at the player's edge, and nothing is lost. The bridge shrinks as views move, and `Extra` stays for what only NetEase's own pages need.

**A refusal is its own kind.** `music.ErrRefused` says the source turned the request away for now, as -460: the track stays, paused, and the reason (`music.Reason`) is the source's own words. It is what `netease.ErrRefused` is today, so nothing about how a refusal plays changes.

**Sessions and the cache keep working.** `session.json`'s queue is read in both shapes (the old `netease.Track` JSON becomes `{Source: "netease"}` tracks, `decodeSession`) and written in the new one. The cache names a song for its source and a hash of its ID, which may hold anything, a path included; NetEase's keep the names they have, `<id>-<level>`, so nothing is downloaded again (`TestCacheKeyNamesFiles`).

**Licence.** Code ported from upstream keeps its licence (AGPL-3.0, ours too) and says so in the file's head. The plugins page lists repositories with the topic `mygo-music-plugin`; the host does not run what isn't installed.

## Stages

1. **The seam** (done 2026-11-24, on `feat/plugins`; MyGo first, then the views):
   1. MyGo v0.10.0, from a v0.7 snapshot. Done 2026-11-24: it builds, tests pass, and the window draws as before. The v0.8 changes that mattered: windows' accents fade when inactive (`InactiveAccent` keeps ours), and `HandleInput` sees every key (our handlers pick by kind).
   2. `internal/music`: the types, `Source`, errors, an embeddable `Unsupported`.
   3. The views, a slice at a time, each one green: the player (queue, stream, lyrics, cover, session, cache), then lists and search, then the library pages (playlist, album, artist), then account, likes and comments, then podcasts and stations; NetEase's extras last. **The player is done** (2026-11-24, on `feat/plugins`): it knows `music.Track`, finds a track's source through `Player.Source`, and imports nothing of NetEase's; `netease.Source` does stream and lyrics (`Can` says so); the views read it through `bridge.go`. **Search is done** (2026-11-24): `Source.Search` serves tracks, albums, artists, playlists and shows, 60 to a page; the search page holds `music` results and draws the artist, album, playlist and show cards from them, which the artist and user pages use too. What stays NetEase's, for the slices that move what it needs: the shared song rows (they read the like state, routes by numeric ID, the song menu, `Alias` and `Reason`, and are fed by pages that still hold NetEase's tracks, so search hands them its songs through the bridge, made once as each page comes in), the suggestions under the search field (NetEase suggests songs, artists, albums and playlists to open, which a source's `Suggest` of keywords has no place for), and the search for users, which no other source has. **The library pages' IDs, likes and song rows are done** (2026-11-24): a route is `{source, id}` as strings, and a card or a row link opens the page of its item's own source; the likes are one map by source and track ID, liked through `Source.Like`, `LikeEpisode` and `IsLiked`; and the shared song rows, with their artist links, heart and menu, take `music.Track` (`Alias` and `Reason` became optional fields of it), fed lazily by `neteaseList` from pages that still hold NetEase's tracks, a row at a time. **The playlist, album and artist pages' data is done** (2026-11-24): each is asked of the source its route names, by the ID there (`Source.Playlist`, `Album`, `Artist`), into maps by source and ID, and drawn from `music`'s types, so a page of another source opens, lists its songs and plays them through their own source; one of a source that is gone says it cannot open. What only NetEase says of each (a chart's update label, who made a playlist, an artist's aliases and counts and the account their events are of) is read back from the record each keeps in `Extra`. Making, renaming, deleting, adding to, taking from and saving a playlist, and following an artist, go through the source. An artist's tabs of NetEase's own (newest songs, albums in pages, events) show only for NetEase; another source's artist has their most popular songs, and their albums if it gives them. **The account and comments are done** (2026-11-24): who is signed in is `music.Account`, asked of the source at start (`Source.Account`, which brings the keychain's session back and forgets one that has run out); signing in is `Source.SignIn`, which shows its QR code and who scanned it through the prompt (`music.Prompter`, with the scanner's name and picture added to `SignInPrompt`) and returns who confirmed, a code that ran out being `music.ErrExpired`, a refusal `ErrSignIn` in the source's words; closing the dialog or signing out gives it up (`music.Canceler`), and signing out is the source's (`SignOut`). The sidebar's made and saved playlists are `Source.Playlists`, the liked songs' being the one the source marks `Fixed`. A track's comments are `Source.Comments` and `LikeComment`, a page at a time with the hot ones on the first (`CommentPage.Hot`, and `Location` and `Reply` on `Comment`), kept by the track's source and ID; a source that does not do them has no comments tab, and one that cannot like them shows the count with no thumb. **Podcasts and stations are done** (2026-11-24): a podcast is asked of the source its route names (`Source.Show`, a page of episodes at a time from where the last ended), held by source and ID, its episodes tracks like any other (`ShowID` says what show; `Unavailable` those with no audio), subscribing is `SubscribeShow` and offered only by a source that can; the podcasts tab lists `Shows`, and NetEase's picks and most popular through an optional interface (`podcastPicker`) no other source need have; the personal FM asks `StationNext`, heart mode and skipping a song on the FM go to optional interfaces too (`heartModer`, `fmTrasher`), the liked songs all at once to another (`likedLister`). **The views are done** (2026-11-24): Now Playing, the stage, the wall, the cover, the notch, the player bar, the sidebar's card and the queue take `music.Track` (`a.current()` and `a.queued()` are the player's own), so a song of another source shows its cover (sized by its URL's `{size}`, or fetched as given: NetEase's size rule applies to NetEase's own pictures only), opens its artist at its source, and is offered no NetEase playlists; the states that followed a track by NetEase's number (lyrics, cover, wall, quiet, captions, comments) follow it by source and ID, a source's episode has its transcript kept by its own ID, and covers are fetched with `music.Fetch`, which reads `file://` too. Editing a playlist, and a song's menu, go by IDs and `music.Track`.

**Stage 1.3 is complete.** What stays NetEase's own, by design, because no other source has it and a plugin cannot supply it through `Source`: its home page (the day's songs, the playlists picked for the listener, featured playlists and charts), users and their pages and events, the suggestions under the search field and the search for users, an artist's newest songs, albums in pages and events, the recent plays a login picks up (`pickUp`), and the NetEase number of who is signed in (`uid`) that those pages need. They read NetEase's package directly and show for NetEase; the app registers one source, `netease.Source{}`, and four places still name it as *the* source to ask (`searchSource`, `accountSource`, `editSource`, `accountKey`). Stage 2 makes those choices (a source switcher, search across sources), draws a source's own `Home` and `Browse` pages for a source that makes them up, and decides what the radio and podcast pages show for a source with stations or shows and no picks.
2. **The host.** `internal/plugin` from upstream, with `plugin.json`, permissions, `fetch` and `host`; a plugin becomes a `Source`; `Player.Source(id)` finds it. Source settings and the switcher. **First milestone done** (2026-11-25): `internal/plugin` is ported (manifest and permissions, the host global with `fetch`, `storage`, `crypto`, `webSignIn`, `waitForRedirect`, `spawn`, request headers, locales, and the `Source` wrapper), on moejs `v0.1.0-alpha.11`, and runs upstream's demo plugin as made (`internal/plugin/testdata/demo`); what it answers is stamped with its source for tracks, albums, artists, playlists and shows. The sandbox is pinned by tests: hosts and redirects, programs and the grant, data folders, pages, a stuck plugin. **Slice 1 is done** (2026-11-25): the player plays what a plugin's `stream` may send (MP3, FLAC, Ogg Vorbis, WAV, ALAC, FLAC or AAC in an `.m4a`, whole or in DASH fragments, and AAC in ADTS; the Ogg and AAC libraries are MIT and LGPL-2.1-or-later, no cgo, about 290 KB more), a `file://` URL plays from where it is without entering the cache, the `headers` a stream names (and the manifest's audio `requestHeaders`) go with its request and stay with its host through a redirect, and the cache keeps a song of any of those types. The app finds plugins in `plugins/` of the user data directory (each one's settings and storage in `plugin-data/` beside it) as it starts, registers each as a source beside NetEase (one whose ID is taken is left out), so `Player.Source` finds its tracks, gives covers the headers a plugin's manifest names, and ends the programs they started as it quits. **Source settings are done** (2026-11-25): the settings window has a group for each plugin (none, and so no change, without plugins): what it may reach, in words; a switch that lets it start the programs its manifest names, which asks first and names them, and takes it back without asking; and the settings it declares, a text or password field kept with Save, a switch or a menu kept at once (a menu keeps the option's value, an unset one says so), each handed to the source off the main thread and, when it cannot be written, said so and not kept for the run either. **Signing in is done** (2026-11-25): a plugin's sign-in can be given up (`music.Canceler`): it ends the call, the loopback port `waitForRedirect` listens on and the page `webSignIn` shows, which were held until they timed out, and closing a plugin or starting another sign-in does the same; the page is a window with a web view in a session that keeps nothing (apart from every page, the listener's browser too), watched for the cookies the plugin named and closed when they are there, the listener gives up or closes it; the sign-in dialog is for any source, with the source's name and its own words from the prompt (`Text`, a code only where it shows one, Cancel or Retry where it shows none), and a plugin's account is the app's per source (`sourceState`), not NetEase's, which stays in its own fields; the plugin's group in the settings has its account row (who is signed in, sign in, sign out, or why it needs setting up first). The web view window itself is not unit tested (no display): the cookie watching is, driven by ticks. **The switcher is done** (2026-11-25): with a plugin installed the sidebar has a button over the search field that says whose music is shown and drops down NetEase and the plugins (without one nothing is added, and NetEase's window is as it was); choosing a plugin starts at its home with nothing of the last source to go back to, and shows its own sidebar: the entries its manifest names (its home, and pages of its own), the last search, and the listener's playlists at the plugin, with its account at the foot; the home and every page of its own are `Browse` pages (`pageBrowse`), drawn with the songs, albums, artists, playlists, shows and links of their sections and a link to the rest, and say where they could not be had what the listener does (sign in, set it up, or try again); a search names its source in its route (`searchSource` is gone), so its results, tabs (no users, which are NetEase's) and later pages are the plugin's, and NetEase's suggestions are not asked for it; the registry of sources is behind a lock. The song row is one function now (`songRow`), which the Browse page uses as the lists do. Not drawn yet for a plugin: the sidebar's stations, shows, saved albums and liked-songs entries (its liked songs are its playlist marked fixed), a station on a Browse page, and suggestions. **The four places that named NetEase are lifted** (2026-11-25): `searchSource` and `editSource` and `accountKey` are gone, `accountSource` is NetEase's own and says so. What needed an account asks by the source of what it concerns: `listsOf` (the listener's playlists at a source: NetEase's in the app's fields, a plugin's in its `sourceState`), `signedInTo` and `signInTo`, `canDo` (a plugin's menus offer only what it exports; NetEase's always did), so a plugin's songs have their heart, comments and follows and its playlists their save, rename, delete, adding to and taking from, through the plugin and its own account, and a plugin that answers `ErrSignIn` to any of them asks the listener to sign in to it instead of showing a failure (`signInNeeded`). **Found by hand and fixed** (2026-11-25): a `file://` song that is not there is said to be missing, where it was called a network failure (a `*fs.PathError` answers as a `net.Error`), and `PathOf` takes what follows `file://` as the path, as a plugin that joins strings makes the URL (a `#`, `?` or stray `%` in a folder's name ended the path or failed the URL); the demo's `tone.mp3`, left out when it was copied, is in `testdata/demo` with a note on trying it by hand; an entry of a manifest's navigation that is the app's own and names no title has the app's, not a blank; a large cover with no picture to come holds a note, as the rows' do (NetEase's covers that are only loading are as they were); and the search field says it searches the plugin shown. **Stage 2 is complete.** What a plugin does not get yet, for want of a page or an entry to put it in: stations, shows, saved albums and a station on a Browse page, suggestions under the search field, and the account's own page; they are `Can` capabilities a plugin may export, drawn when there is a place for them. The registry of sources is locked, as installing a plugin while the app runs (stage 3) changes it under readers.
3. **Installing.** From GitHub, a zip or a folder, `mygo-music://install-plugin` (the scheme goes in `mygo.json`'s `urlSchemes`), updates, removal, a plugins list in settings. **The installer is done** (2026-11-25, `internal/plugin/install.go`, from upstream's): a repository's latest release as the zip for the platform, else a zip of no platform, else its source, else its latest commit; a folder or a zip of this machine; unpacked beside the plugins under a dot, so that nothing is installed or run before the listener says (`Pending`, then `Install` or `Discard`); archives refused whole for a name that leads outside, a link, or more files or bytes than allowed; downloads only from GitHub's API or over https; hidden files stay behind; programs stay runnable; a plugin replaces only what it came from (another repository's, one dropped in, or a plugin of its ID in another folder stay), keeping what it stored; where it came from is `.origin.json`. **Installing, updating and removing in the app are done** (2026-11-25): the settings have a plugins group, there with none installed, whose + installs from GitHub (a repository as `owner/repo` or any of its addresses), a folder or a zip, and shows the plugins' folder; what comes is asked about first, in a dialog that says where it is from, what it may reach and, in words, the programs it asks to run and that they need their own allowing in the settings; each plugin's group says where it came from, checks for a new version when asked and once a day for those from GitHub (one request each, to GitHub alone), offers the update it found, and removes (after a native question, to the trash, its settings staying); a new plugin is a source at once, and an updated one takes the old's place without the app opening again, the old stopped and what the app held of it let go; an update that asks for more than was allowed asks again first, and the programs the old was let run are not the new's. Two things differ from upstream's: its lookup of the listener's GitHub token (`GITHUB_TOKEN`, `GH_TOKEN`, then `gh auth token`) is left out, as the listener never gave this app one and public repositories need none, and the IDs of the app's own sources (`netease`, `local`) are reserved.
4. **Release.** The README's plugin section, `plugins/` in the user data directory, release notes that say plugins run with the permissions the listener allowed.

## Risks

- moejs is alpha (`v0.1.0-alpha.11`). Upstream ships on it, but its behaviour can change.
- A plugin with `network: ["*"]` or `process` can do what the listener can. Upstream asks before installing and before allowing a program; we keep both.
- Every view that reads a track changes in stage 1.3, so the frame and perf tests are the net: they must stay green at every slice, and the Mac checks in [`roadmap.md`](roadmap.md#2-before-0128-blocks-the-release) are run again before a release.
